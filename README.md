# Local Sports Prediction Engine

A self-contained prediction system for soccer (20 leagues worldwide) and the
AFL. Built from open historical data, statistically principled models
(Dixon-Coles + Elo for soccer, Elo + gradient-boosted margin/total for the
AFL), and backtested against real historical closing odds. Runs with no API
keys at all; optional free keys add live fixture and odds feeds.

## Read this first: what "better than Opta/ESPN" actually means here

Opta and ESPN's FPI have things this system cannot replicate offline: optical
player-tracking data, injury newswires, and years of proprietary in-house
tuning. This system does **not** beat them on raw data access, and it does
**not** reliably beat the closing betting market either — nobody's public
model does, consistently, and you should be skeptical of anyone who claims
otherwise. What it *does* give you that Opta/ESPN don't:

- **It's yours.** Runs entirely on your own hardware, on your own schedule,
  with full visibility into every parameter. No vendor, no API rate limits,
  no black box.
- **It's honest about its own accuracy.** Every league is backtested against
  real historical closing odds, and the report is included unedited — see
  `reports/soccer_backtest.json` and `reports/afl_backtest.json`. Out
  of 20 soccer leagues, the model beat the market's own Brier score in **1**
  (English Championship). That's the real, honest number — not a marketing
  claim. Most of the value here is a fast, transparent, tunable *engine* you
  can point at any market feed, not a proven alpha source out of the box.
- **It's built for edge detection, not just "who wins."** The whole point
  for a book is: where does *our* probability disagree meaningfully with the
  market's, and by how much? That's what the edge/Kelly output is for.

Treat this as a serious quant starting point and a decision-support/cross-check
tool — not an autonomous, guaranteed-profit betting system. See "Honest
limitations" below before using this for real stakes.

## Data sources (all free, open, no API key)

- **Soccer**: [Club-Football-Match-Data-2000-2025](https://github.com/xgabora/Club-Football-Match-Data-2000-2025)
  — a maintained mirror combining [football-data.co.uk](https://www.football-data.co.uk)
  results/odds with [ClubElo](http://clubelo.com) ratings. 230,557 matches,
  38 divisions across 27 countries, 2000/01 season through 2024/25, including
  closing 1X2 odds, over/under 2.5 odds, and Asian handicap lines for the
  large majority of matches.
- **NBA**: [sportsdataverse/hoopR-nba-raw](https://github.com/sportsdataverse/hoopR-nba-raw)
  — ESPN-sourced schedule/results data, 2002 through the 2025-26 season
  (32,223 completed games), maintained and updated by the sportsdataverse
  open-source project.

Both are re-downloadable any time with `--refresh` (see below) to pick up
newly played games.

## Methodology

### Soccer: Dixon-Coles + Elo ensemble, per league

Each of the 20 trained leagues gets its **own** model — goal-scoring
environments differ a lot between, say, the Bundesliga and Ligue 2, so
pooling them would blur real signal. For each league:

1. **Dixon-Coles bivariate Poisson** (Dixon & Coles, 1997) — the standard
   academic baseline for soccer scorelines, still the backbone of most
   serious soccer quant work. Every team gets an attack and defense
   strength; expected goals come from `exp(home_adv + attack_home -
   defense_away)`; final-score probabilities come from independent Poisson
   distributions with the classic low-score correlation correction (the
   `tau()` adjustment for 0-0/1-0/0-1/1-1, since real scorelines are
   slightly correlated there). Fit by maximum likelihood with **exponential
   time-decay weighting** (400-day half-life — a match from 3 years ago
   barely counts) and L2 regularization so a newly promoted team with 5
   matches doesn't get a wild, overconfident rating.
2. **Elo rating** — a classic 3-outcome Elo variant (draw probability shrinks
   as a heuristic function of the rating gap), used both as a fast
   cross-check and as an ensemble input.
3. **Blend**: a single mixing weight (`alpha`) between Dixon-Coles and Elo
   probabilities, chosen per league by grid search to minimize log-loss on a
   held-out validation slice.
4. **Calibration, with a guard against overfitting on small samples**:
   Platt scaling (2-parameter logistic regression) is fit on the home-win
   probability, but it's only kept if 3-fold cross-validation on the
   validation slice shows it *actually* reduces log-loss by a nontrivial
   margin. This matters: an earlier version of this pipeline used isotonic
   regression, which looked fine in-sample but measurably *hurt* holdout
   accuracy on some leagues because a few hundred validation matches isn't
   enough data for an unconstrained calibration curve. The guard means most
   leagues now correctly skip calibration rather than fit noise.

Output per fixture: 1X2 probabilities, expected goals, over/under 2.5,
both-teams-to-score, plus (if you supply market odds) de-vigged edge and a
fractional-Kelly stake suggestion.

### AFL: Elo + gradient-boosted margin/total model

1. **Elo**, FiveThirtyEight-style: margin-of-victory multiplier (a 60-point
   thrashing moves ratings more than a 3-point game, damped by the pre-game
   rating gap so upsets aren't over-punished), home advantage, and
   25%-regression-to-the-mean at every season boundary. Home advantage is
   set at 35 Elo points, matching the observed 56.4% home win rate — much
   weaker than an NBA-style figure would be, because several Melbourne clubs
   share the same "home" grounds and gain little real advantage there.
2. **XGBoost regressors** predict the margin and total from strictly
   backward-looking features: rolling 5/10-game margin, offence and defence,
   season-to-date win rate, rest days, finals flag, and Elo. "Strictly
   backward looking" is the important part — the feature pipeline is built
   so a match's own result can never leak into its own features, which is
   the most common way amateur sports-ML looks great in-sample and fails
   out of it.
3. **Venue experience instead of hardcoded geography.** The dominant
   non-strength effect in the AFL is interstate travel: a Perth side
   visiting the MCG is far worse off than a cross-town Melbourne trip.
   Rather than hardcode a team-to-state and venue-to-state map (brittle, and
   wrong for the relocated and Tasmanian home games that dot the fixture),
   the model counts how many of its previous three years of games each side
   has played at *this* venue. A true home ground scores high, a genuine
   interstate trip near zero, a shared or relocated ground in between —
   learned from the fixture rather than asserted.
4. Win probability comes from a Normal model of the predicted margin
   (residual std ≈ 37 points), blended 65/35 with pure Elo. Because margins
   are integers, **draws fall out of the same distribution** as the mass on
   exactly zero, which reproduces the observed 0.78% draw rate without any
   separate calibration.

## Backtest results (unedited, see `reports/` for full detail)

**Soccer** (20 leagues, ~250-700 holdout matches per league from the most
recent ~7.5 months of each league's history, after a separate slice was used
to pick the blend weight/calibration — no double-dipping):

- Average model Brier score: **0.614** vs. average market (de-vigged closing
  odds) Brier: **0.590** — the market is sharper on average, which is
  expected and is the correct prior to hold about betting markets.
- The model beat the market's own Brier score outright in **1 of 20**
  leagues (English Championship).
- A simple "bet when model edge > 4%" simulation across all
  league/outcome combinations showed positive ROI in 22 of 60 segments —
  but many of those have tiny sample sizes (single digits to low dozens of
  bets), which is exactly the regime where you'd expect ~1/3 of segments to
  show positive ROI from noise alone. **Do not read this as proof of an
  edge** — it's a starting point for further validation with more data, not
  a result to size real stakes off of.

**NBA** (654 holdout games from the 2025 season, after a separate slice
picked the blend/calibration):

- Brier score: **0.192** (win-probability calibration) vs. Elo-only baseline
  **0.194** — a small, real improvement from adding the margin model, but a
  modest one.
- Margin MAE: **12.0 points**, total-points MAE: **15.5 points** — in the
  normal range for public power-rating models.
- No static public NBA closing-odds archive was available to pull into this
  offline build, so there's no direct "vs. market" comparison for
  basketball the way there is for soccer. See "Plugging in live odds" below.

## Running it

```bash
# 1. Ingest data (already done once; re-run any time with --refresh to update)
python3 src/ingest_soccer.py
python3 src/ingest_basketball.py

# 2. Train + backtest everything (~6-7 minutes; soccer per-league Dixon-Coles
#    fits are the slow part, NBA takes ~3 seconds)
python3 src/train.py
# or just a subset:
python3 src/train.py --leagues E0 SP1 I1 D1 F1 --skip-basketball

# 3a. Predict from the command line
python3 src/predict_cli.py soccer --div E0 --home Arsenal --away Chelsea \
    --odds-home 1.9 --odds-draw 3.6 --odds-away 4.2
python3 src/predict_cli.py basketball --home Celtics --away Lakers \
    --odds-home 1.55 --odds-away 2.5
python3 src/predict_cli.py leagues        # list trained leagues
python3 src/predict_cli.py teams --div E0 # list teams in a league
python3 src/predict_cli.py nba-teams

# 3b. Or run the local API + dashboard
python3 src/api.py
# open http://localhost:8000 in a browser
```

The dashboard and CLI both read the same trained model files in `models/`,
so anything you can do in one you can script in the other — the API is
there for integrating into a trading desk's own tools
(`GET /api/soccer/predict?...`, `GET /api/afl/predict?...`).

## Live fixtures (no manual team entry)

The dashboard's default tab is "Board" — it auto-loads upcoming
matches grouped by league (soccer divisions + NBA) and runs every one
through the trained models automatically, no typing team names in one at a
time. This is powered by `src/fixtures.py`:

- Upcoming fixtures come from [TheSportsDB](https://www.thesportsdb.com)'s
  free tier (shared "test" key, no signup) via `GET
  /api/fixtures/live`, cached server-side for 30 minutes to stay well
  within the free tier's rate limit.
- Each of our 20 trained league codes (E0, SP1, I1, ...) is matched to
  TheSportsDB's league ID by name, not hand-typed IDs alone — a small seed
  map of IDs I'm fairly confident about is used as a fast path, but every
  ID (seed or fuzzy-matched) is re-verified against the live league-name
  list before being trusted, and two divisions can never resolve to the
  same ID (there's a hard collision guard). That guard exists because of a
  real bug caught during development: matching on the bare competition
  name alone ("Serie A") ambiguously matched *both* Italy and Brazil,
  since neither name is unique on its own — full country + competition
  names are tried first now, short-suffix matching is the last resort.
- Live team names ("Man United") are fuzzy-matched to whatever name our
  trained model actually knows ("Man Utd" or similar) via `difflib`. An
  unmatched team doesn't break anything — the prediction still runs, just
  falling back to league-average strength for that side.
- Resolved league IDs are cached to `data/league_id_map.json` so this
  doesn't get re-resolved on every restart; delete that file (or call
  `/api/fixtures/live?refresh=true`, which also forces a fixture re-fetch)
  to force re-resolution.

**Important caveat**: the sandbox this was built in has an aggressively
allowlisted network — it couldn't reach TheSportsDB, ESPN, football-data.org,
Odds API, or almost anything else external while building this. The
fixtures/parsing/grouping/collision-guard logic was verified locally
against mocked responses shaped exactly like TheSportsDB's real, stable,
documented schema — but the actual live round trip has not been exercised
against the real internet. **The first thing to check after deploying**
(Railway has normal outbound internet access) is opening the dashboard and
confirming fixtures actually populate. If a particular league comes back
empty, it likely just means that league's off-season, but check
`reports`/server logs for entries under `"errors"` in the `/api/fixtures/live`
response first.

## Plugging in live/real odds

This build used publicly available historical odds for soccer backtesting
(football-data.co.uk closing lines) but has no live odds feed, since that's
proprietary to whatever provider a real book uses. Every predict function
already accepts market odds as parameters — `predict_soccer(div, home, away,
odds_home, odds_draw, odds_away)` / `predict_basketball(..., odds_home,
odds_away)` — and returns edge + Kelly stake. To go live, wire your own
odds feed (or another API) into those calls, or hit the `/api/*/predict`
endpoints with your live odds as query params from whatever system ingests
your book's lines. The model side needs no changes.

## Keeping it current

Team strength drifts. Recommended cadence:

- **Soccer**: refit weekly (`python3 src/ingest_soccer.py --refresh && python3
  src/train.py`) during each league's season — Dixon-Coles time-decay means
  stale models degrade gracefully but not indefinitely.
- **NBA**: refit at least weekly in-season; the Elo/rolling-form features are
  the parts that go stale fastest.
- Re-run the backtest report after any material model change and compare
  against the numbers in this README before trusting new output.

## Honest limitations (read before using this for real money)

- **No proprietary data.** No player-tracking, no live injury/lineup feed,
  no referee assignments, no weather. All real edges Opta/ESPN might have
  from those sources are not available here.
- **Backtest sample sizes are modest.** A single season or two of holdout
  data per league is not enough to distinguish genuine edge from variance
  at the individual-bet level, especially in the value-betting simulation.
  Treat the ROI figures as illustrative, not predictive.
- **No live odds/vig data was available in this offline build for NBA.**
  The basketball backtest validates against actual game outcomes only, not
  against a market baseline the way soccer does.
- **Markets move.** Any real deployment needs to compare against *closing*
  lines specifically (not opening lines, which are softer), and treat a
  positive edge as a signal to investigate, not an instruction to
  auto-bet — line movement, limits, and correlated risk all matter and are
  outside this system's scope.
- **This is a starting engine, not a finished product.** The architecture
  (per-league statistical models + ML + calibration + backtest harness) is
  built to be extended: more leagues, player-level data, in-play models,
  and a real odds feed are the natural next steps.
